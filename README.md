# XiOne 文档

XiOne（基于 [new-api](https://github.com/QuantumNous/new-api) 部署）的用户/管理员文档站，
用 [Docusaurus](https://docusaurus.io/) 构建。

这是一个**独立项目**，和 new-api 主仓库解耦：改文档不需要重新构建或发布网关本体，
两者可以部署在同一台服务器上（推荐用子域名区分，见下文）。

## 本地开发

```bash
npm install
npm start          # 开发服务器，默认 http://localhost:3000
```

## 构建

```bash
npm run build       # 产物在 build/ 目录，纯静态文件
npm run serve        # 本地预览构建产物
```

## 上线前必做（搜索文件里的 TODO）

`docusaurus.config.js` 顶部注释列了几处必须替换的占位符：

1. `url` / `baseUrl` — 你的真实域名
2. `organizationName` / `projectName` — 只有用 GitHub Pages 部署才需要
3. `static/img/logo.svg` / `static/img/favicon.svg` — 换成你自己的标识
   （当前是一个占位用的几何图形，不是抄自任何网站）
4. 导航栏和页脚里指向 GitHub / 主站的链接

## 部署

`npm run build` 产物是纯静态文件，任何静态服务器都能托管（Nginx / Vercel / Netlify /
GitHub Pages 均可）。

### 和 new-api 网关部署在同一台服务器

推荐用子域名区分（`docs.your-domain.com`），不要用网关域名下的 `/docs` 子路径——
网关自己在 `/docs` 有一条内置路由，容易撞车。Nginx 配置示例见
`docs/admin-settings/docs-link.md`。

部署好之后，去 new-api 后台「系统设置 → 计费与支付 → 额度设置 → 文档链接」，
填上这个文档站的地址，首页顶部导航的「文档」就会指向这里。

## 内容结构

```
docs/
├── getting-started/   快速开始
├── deployment/         部署方式（Docker / 源码编译）
├── client-setup/        客户端接入指南（Claude Code / Codex CLI 等）
├── payments/           支付网关（含 PayerScan 配置）
├── usage-guide/         平台使用指南
├── admin-settings/      管理后台配置
└── faq/                常见问题
```

侧边栏分类的顺序和标题在 `sidebars.js` 里维护，但每个分类下面的文档列表是**自动生成**的
（`{type: 'autogenerated', dirName: '<目录名>'}`）：往某个分类的文件夹里加一个 `.md` 文件，
侧边栏会自动出现这一条，不用手改 `sidebars.js`。排序看文件的 `sidebar_position` frontmatter，
没写就按文件名排。

新增一个**全新的顶层分类**（比如现在没有的“XX 指南”）还是要改代码：在 `sidebars.js` 加一个
`category` 块，并在 `static/admin/config.yml` 里加一个对应的 `collections` 条目，这两步做完
之后才能在下面的管理后台里编辑那个分类。

## 内容管理后台（Decap CMS）

不想每次改文档都走「clone 仓库 → 改 `.md` 文件 → commit → push」，可以用内置的
[Decap CMS](https://decapcms.org/)（开源、GitHub 原生支持维护的 Netlify CMS 继任者）后台，
在浏览器里直接编辑 `docs/` 下的文件、增删同一分类下的文档，保存后自动帮你提交到
这个仓库。地址是文档站域名下的 `/admin`，比如 `https://doc.xione.ai/admin`。

Decap CMS 的 GitHub 登录默认依赖 Netlify 的 Git Gateway，我们没有用 Netlify 托管，
所以需要自己起一个很小的 OAuth 代理（代码已经在 `server/oauth-proxy/`），流程见
[官方文档](https://decapcms.org/docs/external-oauth-clients/)。上线步骤：

1. **创建 GitHub OAuth App**（这一步必须你自己在 GitHub 账号下操作，我这边没有权限代做）：
   GitHub 右上角头像 → Settings → Developer settings → OAuth Apps → New OAuth App。
   - Homepage URL：`https://doc.xione.ai`
   - Authorization callback URL：`https://doc.xione.ai/callback`

   创建后拿到一个 `Client ID` 和 `Client Secret`（Secret 只显示一次，记下来）。

2. **部署 OAuth 代理**（和文档站同一台服务器即可）：

   ```bash
   cd server/oauth-proxy
   npm install
   GITHUB_CLIENT_ID=xxx \
   GITHUB_CLIENT_SECRET=xxx \
   ALLOWED_ORIGIN=https://doc.xione.ai \
   PORT=8081 \
   npm start
   ```

   生产环境建议用 `pm2` 或 systemd 常驻，不要用前台命令。

3. **Nginx 把 `/auth` 和 `/callback` 转发给这个代理**，其余路径继续走静态文件
   （追加到 `docs-link.md` 里那份 `doc.xione.ai` 的 `server` 块里）：

   ```nginx
   location /auth {
       proxy_pass http://127.0.0.1:8081;
   }
   location /callback {
       proxy_pass http://127.0.0.1:8081;
   }
   ```

4. `nginx -t && nginx -s reload`，然后访问 `https://doc.xione.ai/admin`，
   点 "Login with GitHub" 走一遍登录，能看到左侧按分类分组的文档列表就是配置成功了。

登录用的是你自己的 GitHub 账号，需要对 `qiin/xioneDoc` 有写权限；保存内容时后台会直接
`commit` 到 `main` 分支（`config.yml` 里 `publish_mode: simple`），没有走 PR 审核流程，
谨慎的话可以后面改成 `editorial_workflow` 走草稿 + PR。

`static/admin/config.yml` 里能改的是各分类的字段（要不要加新字段、要不要限制某个分类不能删文件等），
改完直接提交，不用重新构建站点也会生效（Decap CMS 是纯前端读取这个文件）。

## 关于设计

信息架构（左侧任务导向分类 + 顶部搜索 + 右侧锚点目录）参考了同类文档站的通用范式，
但**文案、配色、Logo 均为原创**，不是照抄某个具体网站的实现。改动前可以看一眼
`docusaurus.config.js` 里的自定义主题色（紫色系）和 `src/css/custom.css`。
