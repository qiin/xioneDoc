# 常见问题

### 支付渠道配置好了，前端还是不显示？

先确认「支付合规确认」是否已经完成——任何支付渠道生效之前都需要这一步，没确认的话
所有渠道对用户都不可见，即使各自的开关已经打开。

### 用户付款成功了，但额度没到账？

99% 是回调地址没配对。检查该支付渠道后台登记的 callback URL / Webhook 地址，
是否和网关配置页里显示的一致；Stripe / Creem / Waffo 还需要额外核对签名密钥。

### 一个 API 密钥可以限制只能调用某些模型吗？

可以。创建密钥时可以指定「可用模型」列表，调用列表之外的模型会被拒绝，
和账号本身能调用哪些模型是两层独立的权限。

### 密钥额度和账号额度分别扣的吗？

账号额度是总盘子，密钥额度是给单个密钥再加的一层上限，调用时两边都会扣、
两边都要有余量才能成功。密钥额度用完不影响账号总额度，反之亦然。

### 改了前端代码，构建后线上还是旧的？

浏览器可能缓存了旧的 JS 文件。先确认服务器上跑的确实是新编译的二进制（前端产物是
打包进 Go 二进制的，改前端必须重新 `bun run build` 再 `go build`），再用无痕窗口
或强制刷新（Ctrl+Shift+R）排除浏览器缓存的可能。

### 官方项目更新了，我这边要跟着更新吗？

不是必须的，按自己的节奏来。真要同步时，按仓库根目录 `FORK_CHANGES.md` 里
「同步上游更新的操作流程」执行，一步都不要跳。

### 某个渠道一直报错怎么排查？

先看渠道自己的测活状态，是不是已经被自动禁用；再看该渠道最近的调用日志，
上游返回的具体错误信息通常能直接定位问题（凭证过期、余额不足、模型名不对等）。
