# 使用 Docker 部署

推荐的部署方式。仓库根目录自带 `docker-compose.yml`，覆盖网关本体、数据库和缓存。

```bash
git clone <你的仓库地址>
cd new-api
docker compose up -d
```

首次启动会自动完成数据库迁移。启动完成后，默认监听 `3000` 端口，管理员账号密码见
仓库的部署说明。

## 更新到新版本

按仓库根目录 `FORK_CHANGES.md` 里「同步上游更新的操作流程」执行，不要直接对着
运行中的容器改代码。同步、验证、发布是三个独立步骤，任何一步都不能跳过。

## 反向代理

生产环境建议在网关前面加一层 Nginx 或 Caddy，负责：

- HTTPS 终止
- 把 `/api/*`、`/v1/*` 转发到网关容器
- 静态资源（前端产物）走网关自带的服务即可，不需要单独配置

:::tip
如果你还部署了独立的文档站（就是你正在看的这个），可以和网关共用同一台服务器，
用不同的子域名分流即可，参考 [管理后台配置 → 文档链接](/docs/admin-settings/docs-link)
里的反向代理示例。
:::
