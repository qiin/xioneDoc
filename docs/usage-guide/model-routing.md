# 模型渠道与路由选择

网关会把请求转发给具体的上游渠道（比如你配置的某个 OpenAI 兼容接口、某个云厂商的
模型服务）。这一页说明请求是怎么被分配到渠道的。

## 渠道优先级

管理员给每个渠道设置权重和分组，同一个模型如果配置了多个渠道，网关按权重随机选择，
权重越高被选中的概率越大。某个渠道报错或超时，会自动重试下一个可用渠道，不需要
调用方自己做重试逻辑。

## 模型映射与重定向

如果上游渠道的模型名和你对外暴露的模型名不一致（比如渠道那边的模型叫
`gpt-4-turbo-preview`，你想让用户直接传 `gpt-4`），可以在渠道配置里做**模型映射**，
请求进来后按映射规则转换，用户完全无感。

## 自动分组

大额度请求（比如 `max_tokens` 特别大的调用）可以按 token 数量自动路由到专门配置的
分组，避免和普通请求抢渠道资源。这个功能默认关闭，需要管理员在后台开启并设置阈值。

## 渠道健康检查

渠道可以配置自动测活：定期发送测试请求，连续失败会被自动禁用，避免用户请求一直
打到一个已经挂掉的上游。管理员也能随时手动禁用/启用某个渠道。
